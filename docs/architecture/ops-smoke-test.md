# Ops 运维监控 — 运行时冒烟验收清单

> 配套 `ops-feature-roadmap.md`（M1–M16）。代码已全部实现、单元测试通过、静态检查（vet/build/verify-ent）通过。
> 本文是**运行时验收清单**：需本地起服务、造数据、逐面板核对。任一面板无数据或报错，按「排查提示」定位。

## 0. 前置：起服务 + 造数据

```bash
# 1) 依赖（docker）：PostgreSQL + Redis
# 2) 后端（airgate-core/）
make dev-backend          # 或 make dev 全量热重载
# 3) 前端（web/）
pnpm dev
# 4) openai 插件（airgate-openai/）dev 模式加载（config.yaml 配 dev 插件）
```

**造数据**：用 openai 插件发若干请求——
- 正常请求若干（成功样本）
- 故意用错误 key / 不存在模型（制造 4xx/5xx 错误样本）
- 流式请求若干（产生 TTFT 样本）
- 客户端带 `X-Request-Id` 头（验证 trace：同一 id 跨账号重试会串成链路）

> 数据落库后：实时面板秒级出现；趋势/聚合窗口约 **1 分钟**后出现（聚合器每分钟跑一次）。

## 2. 排查提示

| 现象 | 可能原因 | 排查 |
|---|---|---|
| 所有面板空 | 插件未上报 / 未发请求 | 看后端日志有无 `ops_report`；确认插件声明了 `ops.report_request` capability |
| 趋势图空但实时有值 | 聚合器未跑满 1 分钟 | 等 1 分钟；查 `ops_aggregation` 任务心跳 |
| 系统资源 DB/Redis 为 0 | 注入未生效 | 确认 `main.go` 调了 `SetDBStatsFunc`，`server.go` 调了 `SetRedis` |
| 实时徽章红点 | SSE 连接失败 | 浏览器 Network 看 `/ops/stream` 是否 200 且持续；反代需放行 SSE（关闭缓冲） |
| 告警不触发 | 评估锁 / 冷却 / 静音 | 查 `ops_alert` 任务心跳；确认规则 enabled、不在冷却期、无静音 |
| 告警邮件没收到 | SMTP 未配 | 设置里配 SMTP 并用「测试」验证 |
| trace 无关联 | 入站无 `X-Request-Id` | 客户端或网关需带稳定请求 ID 头 |
| 日志级别切了不生效 | LevelVar 未共享 | 确认 `main.go` 用同一个 `slog.LevelVar` 建 baseHandler 与 LogSink |

## 3. 已知能力边界（非缺陷，见 roadmap）

- **M7 用户维度**未做：scheduler 未暴露用户槽位批量计数接口。
- **M12 分段延迟**未做：airgate-sdk 的 `ForwardOutcome` 不带分阶段耗时（需改 SDK）。已实现模型映射 + trace 关联。
- **M5 用 SSE 而非 WebSocket**：单向推送场景等价，零新增依赖、走现有 header 鉴权。
